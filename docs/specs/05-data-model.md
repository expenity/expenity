# 05 Data model

PostgreSQL. All IDs are UUIDs generated by the client where possible. Every table has `created_at`, `updated_at`, and (for user content) `deleted_at` for soft delete. Every household-scoped table has `household_id` with RLS.

```
users ──< household_members >── households
households ──< categories
households ──< bills ──< occurrences ──< payments
bills ──< reminder_rules          (null bill_id = household default)
occurrences ──< reminder_jobs ──< deliveries
bills / payments ──< attachments
households ──< invitations, calendar_tokens, activity_log, draft_captures
users ──< notification_channels
```

## Tables

**users**: id, email, display_name, locale, timezone, quiet_hours (start,end), avatar_url.

**households**: id, name, base_currency, country, default_reminder_policy (JSON), plan (`free|pro`), plan_expires_at.

**household_members**: household_id, user_id, role (`owner|member|viewer`), joined_at.

**invitations**: id, household_id, email?, token, role, expires_at, accepted_by.

**categories**: id, household_id, name, icon, colour, sort_order, is_system.

**bills**: id, household_id, name, payee, category_id, amount_type (`fixed|variable|unknown`), amount, currency, estimate_amount, recurrence_rule (RRULE text, null = one-off), starts_on, ends_on, installments_total, autopay (bool), assignee_user_id, pay_url, payment_reference, iban_or_account, notes, tags[], is_subscription (bool), cancel_url, archived_at.

**occurrences**: id, bill_id, household_id, due_date (date), expected_amount, status (`upcoming|paid|skipped`; *overdue* and *due today* are derived), installment_no, paid_at.

**payments**: id, occurrence_id, household_id, amount, currency, fx_rate, paid_on, paid_by_user_id, method?, note.

**reminder_rules**: id, household_id, bill_id (nullable), steps (JSON array: `{offset_minutes, channel, repeat_every_minutes?, until_paid?}`), enabled.

**reminder_jobs**: id, occurrence_id, recipient_user_id, step_index, channel, fire_at (timestamptz), status (`pending|sent|failed|cancelled`), attempts, idempotency_key (unique).

**deliveries**: id, job_id, channel, provider_message_id, status, error, delivered_at, opened_at.

**notification_channels**: id, user_id, type (`webpush|email|telegram|sms|whatsapp`), address/endpoint, keys (for push), verified_at, last_success_at.

**attachments**: id, household_id, owner_type, owner_id, storage_path, mime, size, kind (`bill|receipt`).

**draft_captures**: id, household_id, source (`upload|email|csv|text`), raw_ref, extracted (JSON with per-field confidence), status (`pending|accepted|rejected`).

**price_history**: bill_id, occurrence_id, amount, observed_on (feeds price-increase insights).

**calendar_tokens**: id, household_id, user_id, token_hash, revoked_at.

**activity_log**: id, household_id, actor_user_id, action, entity_type, entity_id, diff (JSON).

**subscriptions_billing** (for Expenity's own plans): household_id, stripe_customer_id, stripe_subscription_id, status.

## Derived concepts

- *Overdue* = occurrence `upcoming` and `due_date < today` (in household timezone).
- *Annualised cost* of a subscription = amount × occurrences per year.
- *Forecast* = sum of upcoming occurrences' `expected_amount` (converted to base currency) by date.

## Indexes worth having

`occurrences(household_id, due_date, status)`, `reminder_jobs(status, fire_at)` partial on `pending`, `bills(household_id, archived_at)`, unique `reminder_jobs(idempotency_key)`.
